**Audit verdict: the merge is directionally sound, but it is not yet a validated unified experiment. No stock model in the current evidence is convincingly established as having an evaluation-specific causal effect on refusal. Several models clearly respond to inserted safety-related reasoning. Those are different claims.**

Audit of commit `138f483`, September 28, 2026. The existing modification to `scripts/run_unified_interventions.sh` predates this audit. I changed no production code, experiment data, judge labels, or existing results; I added only this audit directory. No GPU experiments were launched or stopped.

**What is supported now**

The key distinction is between (a) producing evaluation-related language, (b) changing refusal after an evaluation-related sentence is inserted, and (c) changing refusal specifically because of evaluation framing, beyond matched safety/manipulation language. The current work supports (a) and, for several models, (b). Evidence for (c) is weak. None of these alone establishes that a model recognizes real evaluation versus deployment, or strategically conceals behavior.

The source paper itself defines verbalized eval awareness without assuming an internal belief or evaluation/deployment discrimination, and its sentence intervention experiments concern Kimi K2.5. Our broader question needs stronger identification than merely reproducing its verbalization measure. [Original research](https://www.goodfire.com/research/verbalized-eval-awareness-inflates-measured-safety).

**What Claude combined well**

The first-10 design avoids pooling adaptive high-VEA top-ups into the primary prevalence estimate. The exclusion union, common refusal answer view, full-CoT calibrated VEA judge, and shared Mantel–Haenszel estimator are sensible harmonization choices. Importing the original boundary and seed helpers avoids an unnecessary second implementation. The new insertion arms share seeds within each base. Refusal judging correctly uses `prompt_qid`, not the synthetic continuation `qid`. The new removal contrast does not apply the legacy rejection filter.

I recomputed every saved primary and secondary metric and bootstrap interval for the four unified models: all matched exactly (`full_recompute.json`). The primary files contain all 4,860 expected question/index slots per model before scoring exclusions; every scored primary rollout has VEA and refusal labels. There are no duplicate unified rollout keys. I separately checked the MH formula against an unequal-sample-size hand calculation, and recomputed the Qwen3-32B insertion contrasts from its verification CSV. These checks support the arithmetic; they do not validate the labels or causal interpretation.

All 498 saved removal bases for the four local models contain the entire quoted evidence inside the removed token span. None starts its removal at token zero. Removed spans range from 5 to 65 tokens across the models, with medians 18–23 tokens (`splice_checks.json`). Saved sampling records match the intended settings, including Nemotron top-k=0; I checked the installed Transformers behavior rather than assuming an older default.

**Confirmed bugs and integration defects, in priority order**

1. **P1 — Retried trajectories invalidate the claim of exact retrospective cap harmonization.** `src/eval_awareness/unified.py:104` selects the last version of each rollout; `generate.py` retries only outputs that hit the original total-length cap. The retries are different trajectories in the actual files, even with the same seed. Among current primary rows, 18 Nemotron, 4 Qwen3.5-122B and 39 Qwen3.5-397B rows pass the unified cap although their original trajectories did not. Some originally scored trajectories also changed. This selectively gives originally long trajectories another chance to enter the scored population; it is not simply cutting the original rollout at 8,192 tokens.

   Fix by choosing the first generation attempt for the primary capped design, preserving attempt provenance, and judging the corresponding original text where necessary. Keep the last-attempt analysis as a sensitivity. Do not reuse retry labels on original text. Excluding all changed retries barely changes the current within-question point estimates: Nemotron 7.83→7.93, 122B 2.94→2.96, 397B 1.28→1.31 points. This is reassuring about those headlines, but exclusion is a sensitivity, not an exact repair (`retry_sensitivity.json`).

2. **P1 — Invalid VEA judge outputs are silently counted as negative and permanently considered complete.** `rubrics.py:133` returns `(False, None)` when `QUOTE:` is absent. `judge.py:228` logs `parse_ok=False`, but `unified.load_table` drops that flag and `metrics` counts the false label. I found 26 such failures among scored unified rows across the four models, including top-ups/excluded prompts; 17 enter the primary tables: 2 Nemotron, 10 122B, 5 397B. These are not huge enough to explain the major patterns, but they are actual mislabeled missing data. The parser also accepts a `QUOTE:` inside unfinished judge reasoning in an isolated reproduction.

   Return missing/invalid on malformed output, require a completed verdict, retain parse state through analysis, and explicitly retry invalid judgments. Preserve the mandated logical resume keys; add input/config fingerprints and validity checks alongside them. Retrying unchanged commands currently skips invalid labels because `judge.py:191–202` treats every existing key as done. Do not edit the verbatim F1/F2 rubrics to solve a parser problem.

3. **P1 — Unified artifacts can freeze incomplete input forever.** `unified.build` (`unified.py:162–177`) skips an existing output file without checking source growth, completeness, or provenance. It also skips judgment reuse after a crash between writing rollouts and copying labels. `reuse_mine_judgments` and `intervene_unified.convert_ladder` likewise treat mere file existence as completion. A build during an append, interrupted build, or conversion before all VEA judgments exist can therefore remain permanently incomplete. I reproduced the existing-file skip with a temporary fixture. `io.read_jsonl` also fails on a torn final JSON line, contradicting a strong interpretation of “safe to kill and rerun.”

   Use a validated snapshot/manifest and atomic completion marker, or append missing logical records with explicit source-version handling. Build selected bases only after coverage checks pass. Preserve original artifacts and create versioned derived outputs when inputs change. Recover a torn trailing append deliberately; never silently ignore corruption in the middle of a file.

4. **P1 — Partial runs can produce success messages and misleading final-looking reports.** `scripts/run_unified.sh:32–47` echoes failures, then prints “done” and “all judging done” with success status. The ladder wrapper does not stop subsequent phases on these failures. `unified.metrics` reports `n_rollouts` as all scored rows, while separately computing rates over whatever labels exist, without reporting the label denominators. The four current tables have full coverage, so this has not corrupted their present denominators. It is a concrete risk for the pending ladder integration. `intervene_unified.contrasts:293` also crashes with `KeyError: ['none']` on a valid in-progress file containing only the VEA arm; reproduced.

   Aggregate subprocess exit status, validate expected models/keys/conditions and parsed-label coverage, and distinguish partial monitoring output from final analysis. Report generated/scored/judged/valid counts separately. Do not treat eight requested continuations as eight observed outcomes.

5. **P1 — The intervention analysis drops treatment-dependent missing outcomes and removes useful diagnostics.** `intervene_unified.py:318` excludes unscored/unjudged continuations before calculating condition means. The original ladder analysis at least reports per-condition scoring rates and re-verbalization proxies; the unified version drops these diagnostics. Thus its contrast is a difference among observed outcomes, not automatically the effect on all assigned continuations. Saved ladder condition scoring rates differ and can be as low as 97%; that scale matters for reported effects of 1–3 points. This is an analysis/design issue, not evidence that every estimate is biased by 3 points.

   Retain all assigned rows, report missingness and reasons by arm/base, and add worst-case outcome bounds or a clearly defined composite endpoint. Pairwise-complete analysis is a useful sensitivity, not a general cure for post-treatment selection. Report complete base counts and question counts. Keep a calibrated re-verbalization/manipulation check as a mechanism diagnostic, without conditioning the primary refusal estimate on it.

6. **P2 — The subtree merge broke the reference submodule.** The gitlink exists at `ladder/third_party/Non-verbal-Eval-Awareness`, but its mapping remains only in `ladder/.gitmodules`, with an unprefixed path. There is no root `.gitmodules`. `git submodule status` fails: `fatal: no submodule mapping found in .gitmodules for path 'ladder/third_party/Non-verbal-Eval-Awareness'`. The reference directory is empty. Exp01 reconstruction/scoring imports cannot work as documented.

   Add a root submodule mapping with the prefixed path and preserve the pinned commit `6975868bfa3bdbbd81af3fe04d1c5ca799acffe8`; initialize it explicitly. Also document the remaining legacy `/workspace` environment/model paths if exp01 or the old launchers are meant to run on this host. This does not block the current unified four-model analysis, but it is a real incomplete merge.

7. **P2 — Ladder removal acceptance checks only the quote's start.** `intervene_unified.py:258–260` accepts a removal base when the first character/token of the new judge's quote lies in the removed span. It never checks the quote's end, despite claiming the quote is inside the span. A quote spanning several sentences can therefore be accepted even if its evaluation evidence extends beyond the removed text. Check full span containment, then retain the exact removed text for inspection. Impact cannot be quantified until the ladder cache arrives; the 498 local-model spans did pass the stronger full-containment check.

8. **P2 — Empty answers violate the stated scored definition.** `unified.py:114–119` distinguishes only `response is None`; `response=''` becomes scored. The new continuation generator similarly assigns scored after finding the closer without verifying a nonempty answer. The ladder generators have the same inherited weakness. The refusal judge then grades an empty answer as if it were substantive output. Reproduced in an isolated builder test. No such empty-scored answer was found in the current four-model unified rollout files or the inspected Gemma continuations. 9. **P2 — Provenance is weaker in the merged path than in the ladder.** Unified generation stores seeds and prefix lengths, but no complete immutable manifest of source hashes, model/tokenizer revisions, sampling parameters, code revision, chosen bases and rendered prompt/token hashes. `jobs_for` assigns synthetic qids by enumeration; regeneration of the base list changes their meaning, while resume/judging trusts the same qid. `data.load_fortress` and local model/tokenizer loading use unpinned revisions.    Keep the logical keys unchanged, but bind them to a versioned manifest and reject mismatches. Require a new artifact version when the design changes. For the pending cache transfer, copy the complete necessary cache metadata, especially `exp02/prompt_prep.json`: `ladder_generate.cache_paths` reads it to resolve content-addressed generation paths. The presence of `exp02/generations/` alone is not a sufficient preflight check.

**Scientific limitations that fixing code will not solve**

The within-question MH estimator is a reasonable descriptive summary. It controls prompt identity, not the stochastic reasoning trajectory, perceived harmfulness, or a refusal decision already forming before the VEA sentence. Longer or more cautious trajectories may both verbalize testing and refuse. Length adjustment can be informative, but reasoning length itself can be downstream of the same process. Correlation cannot identify which models are causally eval aware.

The manipulation sentence is an active control, and an appropriate one for asking whether *evaluation framing adds anything beyond recognizing a harmful/manipulative request*. Matching its effect does not prove evaluation wording is causally inert: both can trigger a shared process. Conversely, comparing an eval sentence only with nothing does not isolate evaluation meaning. “The control subtracts out the mechanism” is a possible interpretation, not evidence that the mechanism is evaluation awareness. Report both total sentence effects and the specific VEA−manipulation contrast.

Removal currently compares two different prefix lengths and contents, resampling after versus before a sentence. It intervenes on the whole sentence, which can include danger recognition, safety policy, uncertainty, or an intended response. It does not intervene directly on a latent belief. The prefix may already contain earlier VEA, and the removed arm may regenerate it. A null is not proof that natural awareness has no effect; a positive result is not automatically specific to awareness. A meaning-matched replacement or a factorial intervention is stronger than bare deletion.

The legacy rejection-filtered removal estimate is particularly unsuitable as primary causal evidence: it discards continuations based on their post-treatment re-verbalization. The proposed Wald adjustment additionally needs exclusion and other IV assumptions; deleting a sentence changes more than binary VEA presence, so those assumptions are not established. Keep these as explicitly conditional/exploratory quantities. The unified unfiltered contrast is an improvement. `results/CROSS_MODEL_REPORT.md` should not lead with “VEA has a causal effect on Nemotron's refusal” without restricting that claim to the tested sentence edits and acknowledging failed specificity.

Cross-model differences in intervention effect also mix different selected question populations. Each model uses its own contested prompts and its own source reasoning; the ladder and local code additionally select using different historical refusal judges. This is compatible with valid within-base contrasts, but it does not yield an unconfounded ranking of model susceptibility. Report per-model estimands and a common eligible-question sensitivity when feasible. Do not interpret a difference in statistical significance as a significant difference between models.

The 384-token answer view harmonizes stored data, but it measures refusal in the visible prefix. Later compliance is unobserved. Overall 96% judge agreement between answer views does not guarantee negligible treatment-effect bias: the same comparison reports Qwen3.5-397B refusal moving from 70% to 78% on its 60-answer sample. Validate answer truncation on intervention outputs by condition where full outputs exist. Existing ladder artifacts cannot recover discarded answer tokens without new generation.

Judge selection is defensible, but validation remains thin. The 146-example calibration labels came from Claude and were used to write the calibration notes; they are not held-out human accuracy. Ten wins on thirteen human-labeled disagreements favors one judge on disagreements, not a population precision/recall estimate: the judges can agree and both be wrong. The historical 39-answer human refusal audit concerns the old ladder judge and a stratified sample. It does not validate the replacement F2 judge on all models/arms. Audit both judge-positive and judge-negative items, blinded and stratified by model/condition, retaining sampling weights when estimating population accuracy. The current quote check found 13 failures among scored VEA-positive unified rows (including selected top-ups/excluded prompts); some may be paraphrase/formatting rather than hallucination. Restore this diagnostic in unified reporting rather than automatically accepting or deleting them.

Multiple comparisons matter: twelve ladder models, multiple insertion contrasts, removal, and many observational variants make a single nominally positive result unsurprising. Qwen3.5-4B's +3.2-point specificity and Qwen3-32B's +2.7-point removal deserve follow-up rather than definitive labels. Prespecify the family of tests, meaningful effect threshold and confirmatory contrast. For claims of absence, use an equivalence margin justified by the application, not merely a CI crossing zero. CIs conditional on these judges omit systematic judge error.

The logit monitor is a teacher-forced phrase preference, not a calibrated detector of a latent evaluation belief. Benchmark versus chat wrappers changing that preference is evidence of linguistic/context sensitivity. The harmful/benign disguise groups are sampled separately; subtracting average shifts does not exactly eliminate wrapper and length effects. Self-recognition is also a different construct: choosing another model's CoT does not disprove awareness of being tested. The self-recognition code's two-way bootstrap for reused CoTs is a good feature, but its confidence-only AUROC should not be read as P(self) discrimination without taking YES/NO direction into account.

Finally, historical reports do not all estimate the same thing. The original `analyze.py` uses rollout-binomial error bars rather than prompt clustering; `followup.py` uses n1*n0 weights rather than n1*n0/N and computes correlations on selected VEA prompts. The unified Spearman calculation includes all jointly judged prompts; the legacy replication restricts to prompts with VEA. These are different estimands, not numerical replications of the same claim. The code correctly retires much of this history, but the cross-model report and AGENTS status should explicitly identify which conclusions have been superseded.

**How close this is to a defensible conclusion**

A narrow conclusion is close: several Qwen3 models show substantial refusal changes from inserted safety/manipulation language, with no detected incremental benefit from evaluation framing in the present comparisons. Human verification already supports that wording for Qwen3-14B/32B under the old judge. The pending rejudging should test robustness, not erase the old outcomes.

A definitive list of models with evaluation-specific causal awareness is not close enough to publish yet. The pending merged experiments improve comparability but mostly repeat the same identification limits. At the final audit snapshot, Gemma generation was active with 2,400 of 4,160 planned continuations written; `ladder/cache/` was absent, and there was no unified intervention summary. Saved local bases are: Gemma 106 insertion/48 removal (27 removal questions), Nemotron 150/150 (109), Qwen3.5-122B 84/150 (107), Qwen3.5-397B 80/150 (92). “150 bases each” is a target, not the achieved sample size. Additional continuations cannot replace missing independent questions.

The shortest useful path forward is:

1. Preserve the current run artifacts; add coverage/provenance checks and parse-failure repair before treating unified outputs as final. Do not change a running shell script in place or silently mix changed generation settings into a resumed file.
2. Correct the original-attempt/cap analysis in a new version, and finish cache transfer, ladder relabeling and the four ongoing intervention sets. Fix full-quote containment before accepting ladder removal bases. Recompute all derived tables with a clear snapshot/version.
3. Report VEA−none and VEA−manipulation together, unfiltered removal, condition scoring/parse rates, re-verbalization, base/question counts, and missing-outcome bounds. Validate F2 on a blinded sample of these actual intervention answers.
4. Before more large-scale sampling, specify the causal claim and confirmatory tests. Prioritize Nemotron (large cue responsiveness), Qwen3-32B (natural-removal candidate), and Qwen3.5-4B (exploratory specificity candidate). Use fresh questions/bases or clearly separate confirmatory data. A factorial design crossing evaluation context with safety salience, plus matched natural-sentence replacements, would test specificity more directly. Include coherence and benign over-refusal checks. This is a proposed design, not a launched experiment.
5. If the goal specifically includes recognizing evaluation versus deployment, add that as a separate matched-context behavioral test with stable task content and a working positive control. Do not infer it solely from verbalized “testing boundaries.”
